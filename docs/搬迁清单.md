## 0. 搬迁原则（硬）

1. **搬迁不重写**：包整个带测试搬（`git filter-repo --path` 或 `git subtree split` 保留历史）；禁止「看旧代码重写一遍」。退化取证仍可在归档仓 `git log`/`blame`。
2. **入场有门**：每包搬入同时完成——落部门目录、`dNNN_` 文件改按关注点命名、D# 注释只留仍约束行为者（其余改写为行为描述）、`docs/modules/<pkg>.md` 补页、import 方向过 §3 红线脚本。
3. **数据一行不动**：DB 实例不换；新仓 `migrations/0001_baseline.sql` = 当前生产 schema dump（含 `schema_migrations`→置为 baseline 版本）；不搬的表随「不搬」裁定在切流票里 `pg_dump` 归档后 DROP。
4. **纪律原样继承**（§6）。
5. **D# 续号不重置**：新仓 `decisions.md` 自 D-212 续；D-001~D-211 引用直接写号，出处=归档仓。

## 8. 切流与回滚

切流（复审席执行，一次完成）：
1. 旧容器 `docker compose stop arb-core`（保留 standby 7 天，`/opt/arb-archive` 的 compose 文件改容器名 `arb-core-legacy`）。
2. 新镜像 `docker build -t arb-core:latest` → `docker save | ssh load` → SG `/opt/arb` 替换为新仓同步树（`scripts/deploy_sync.sh`）→ `compose up -d`。
3. baseline 迁移：`schema_migrations` 对齐 + `0002` DROP（dump 先落 `/opt/arb-backups/d212-archive/`）。
4. cron 指向新仓 `scripts/` 权威版（路径不变故零改动，核一遍）。
5. 验收：对等闸 1–7 在 SG 复跑；首个 selfwatch 日报/周报到达；`[施工完成:M3] @<hash>`。

回滚：`compose up -d arb-core-legacy` + `0002` 的表从 dump `pg_restore`；7 天后无回滚则删 legacy 容器与镜像。
