## 2. 逐项借鉴明细（对到我们活票上）

### 2.1 Hummingbot——直接对位 funding_carry/term_basis 家族
- **借**：v1.27 官方 FRA 脚本的**窗口语义**（funding 结算窗×持有期×费用年化的口径——正是我们 hh 假费票要对的表）；跨所做市（XMSS）的**库存偏斜模型**（对敞口帽下的双腿再平衡有直接参考）；连接器层的**限速/交易所怪癖处理模式**（对 egress 振荡下的退避也有参考）。
- **不借**：Python 运行时、其策略容器整体（我们模板引擎已有）。
- **对票**：hh 输入源修票（口径对照）/机会面四步序③判据。

### 2.2 NautilusTrader——抄「研究-实盘同核」架构思想
- **借**：其 2026-03 官方阐述的 parity 三件套——**同一 kernel、同一事件序、同一时间处理**横跨回测与实盘。我们的 paper→毕业管线共享代码但**不共享事件/时间语义**（paper 用历史帧、live 用流事件——这正是判据失真的温床）。落法（Go 内）：paper 轨改喂**与 live 同构的事件流**（回放 facts/ticks 为事件帧而非点查）——与 D-633 分层（现态读面统一）同向，可并票。
- **不借**：Rust 核心（我们无延迟需求）、Python 控制面。
- **对票**：毕业判据票的「置信界怎么算才不骗人」面。

### 2.3 Freqtrade——抄 edge 仓位法与 protections 防护
- **借**：①**edge 模块**=胜率×期望值驱动的仓位分配（活体实现了我们《策略评估与仓位》skill 的 Vince 方法论——看它怎么处理小样本置信界）；②**protections**（冷却/连败停/回撤锁）=我们的硬线（连败锁 5/30 日 −3%）的成熟代码形态参考；③dry-run→live 的切换语义。
- **不借**：整体框架、Telegram 机器人形态。
- **对票**：硬线数学化（kill 扳机票族）未来的实现参考。

### 2.4 aoki-h-jp/funding-rate-arbitrage——hh 口径的对照答案
- **借**：轻量纯 FRA——**其对「资金费分歧→建仓→持有多久→费怎么摊」的默认语义**，就是 hh 假费票的第三方对照答案（我们的 3h vs 它的天级默认，谁对一眼见）。
- **对票**：hh 输入源修票（直接对照件）。

### 2.5 gocryptotrader——Go 原生连接器模式
- **借**：多所连接器接口抽象/认证轮换/限速器分层的 Go 惯用法（若未来扩所，抄形不抄码）；注意其「开发中非生产就绪」自述——只当参考读物。
- **对票**：能力账扩所面（未来）。

## 3. 落地路径（怎么借不踩债）

1. **阅读票制**：每项借鉴=一张小票「读 X 仓的 Y 模块→产出一页能力账/skill 增补」——产物入我们自己的 docs/能力账 或 skills/，**不 fork 不 vendor**；
2. **口径对拍优先**：第一批只做两个对照（Hummingbot FRA 窗口语义 + aoki hh 默认）——直接喂给 devin 的三发现证实流程；
3. **架构思想缓行**：Nautilus 同核思想并入 D-633 分层票族讨论（现态/历史分层本就是半个同核），不另起大票；
4. **禁线重申**：零新运行时依赖；抄进代码的任何片段过完整票+复审+机检。
