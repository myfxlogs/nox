# 策略产生方法论升级设计

> 业主令 2026-10-19：跨语言提炼开源量化框架的核心思想（非照搬源码），对齐 NOX ≥8% 目标。
> 状态：**草案——业主与决策席讨论后拆票**。

## 0. 问题定义

NOX 当前策略开发的核心瓶颈不是策略种类不够，而是**验证速度**：

| 阶段 | 耗时 | 瓶颈 |
|---|---|---|
| 假设→S1 memo→S2 桥 | ~1h | 无（已自动化） |
| S2→paper 开仓 | ~1h | 无 |
| **paper→毕业** | **5-21 天** | 🔴 串行等待——一套参数跑完才知道结果 |
| 毕业→armed→真金 | ~1h | 无 |
| armed→发现退化/kill | 数天-数周 | 被动等亏损发生 |

**每增一个策略参数组合=多等 5 天**。这不是策略不够多，是迭代不够快。

## 1. 五项思想（来自开源框架的核心洞察，非源码搬移）

### ① 参数空间回测（来自 vectorbt）

**vectorbt 做对的不是快，是「先扫参数空间再上」**：

```
NOX 现状（串行探索）：
  假设 → paper（一套参数）→ 等 5 天 → 看结果 → 调参 → 再等 5 天
  一个策略参数验证 = 2-3 周

vectorbt 思想（批量探索）：
  假设 → 回放历史 × 100 组参数 → 秒级出 PnL 矩阵 → 选最优 2-3 组 → paper 确认
  一个策略验证 = 1 天回测 + 5 天 paper 确认
```

**NOX 落法**：
- 已有：历史数据全在库（facts 500 万行、ticks、snapshots）+ detector/gate/evaluator 是纯函数
- 缺：一个 `tools/backtest` 回放引擎——读历史 facts 逐拍喂入既有判定链，参数从 app_config 读
- 参数每组跑一遍记录：PnL 曲线 / 最大回撤 / 夏普 / 息差覆盖率 / 退出次数
- 产出物：参数-PnL 矩阵 → 最优参数窗 → 进 paper 确认（paper 闸不撤——回测通过≠免检）

**对 ≥8% 的贡献**：策略迭代速度 ×5（5 天→1 天），同一时间段可验证 5 倍参数组合。

### ② 因子组合（来自 Zipline pipeline / QuantConnect alpha model）

**它们的突破：策略不是原子，是因子的组合**：

```
NOX 现状：
  funding_carry 检测器（看 funding）
  cfd_swap_carry 检测器（看 swap）
  term_basis 检测器（看 basis）
  → 检测器独立、判定条件硬编码、新增组合需新检测器

Zipline 思想：
  因子库 = {funding_rate, basis_ann, swap_rate, volume_24h, volatility, spread_bps}
  策略 = 因子表达式（"funding > 3×earn_apr AND basis < entry_threshold AND vol < X"）
  → 策略空间从 N 检测器爆炸为 N×M 因子组合
```

**NOX 落法**：
- `fin_opp_hypothesis.params_proto` 已是 JSON——扩为因子表达式 `{factors: [...], condition: "funding > 3×baseline && basis_ann < 5%", sizing: {...}}`
- detector 从硬编码阈值升级为读表达式执行（一个通用 detector 替 N 个专用）
- S1/S2 管线产出的假设自动带因子表达式（LLM memo 可建议因子组合——顾问非掌权不变）
- 与①配合：因子组合空间可批量回测

**对 ≥8% 的贡献**：策略空间扩大——同一底层资产可在不同因子条件下产生不同策略。

---

### ③ 市场状态检测（来自 regime-aware 框架）

**通用洞察：同一策略在不同市场状态下表现截然不同**：

```
NOX 现状：
  所有 armed 组合常开——WTI carry 死引擎（funding 衰零）还挂着
  高波动期和低波动期同一仓位

Regime 思想：
  检测市场状态 → 匹配策略适应域
  trending → 暂停 mean-revert
  高波动 → 缩小 carry 仓位
  流动性骤降 → 暂停新开仓
```

**NOX 落法**：
- 一个轻量 regime 检测器：用已有 facts 数据算 3 个指标（波动率/趋势强度/流动性代理）
- 输出状态标签：`{calm, trending, volatile, illiquid}`
- armed 组合评估环读标签：不适配状态→不产机会或降仓
- 与 kill 扳机互补：kill=事后淘汰，regime=事前避免

**对 ≥8% 的贡献**：减少在不适合的市场状态亏钱——不是多赚，是少亏。

---

### ④ 仓位=函数（来自 Kelly criterion / 学术金融）

**NOX 现状**：固定 cap（$700/组合）——不论策略质量、不论市场状态、都是同一个数。

**思想**：仓位 = f(策略历史胜率, 盈亏比, 当前市场不确定性)：

```
简单 Kelly：f* = (bp - q) / b
  b=盈亏比, p=胜率, q=1-p
  胜率 60%、盈亏比 1.5 → f* = 33%（给 33% 可用资本）
  胜率 40%、盈亏比 1.5 → f* = 0%（不给仓）
```

**NOX 落法**：
- `decision_outcomes` 归因簿已在记每个策略/组合的胜率、盈亏——数据现成
- gonum `stat` 包算置信区间：胜率置信下界越线才给仓
- sizing 公式：`position = min(kelly_f * available_cap, max_gross)` —— kelly 是上限建议，max_gross 硬线不动
- 新策略无历史数据→默认最小仓位（保守档），攒数据后 Kelly 优化

**对 ≥8% 的贡献**：好策略多给仓、差策略零仓——资本效率提升（同样 $10k 分配给胜率更高的策略）。

---

### ⑤ 策略前提检验（来自 NautilusTrader 的 determinism 思想）

**思想**：策略好不好不是「跑着没亏」而是「还在做它声称做的事」：

```
carry 策略声称：息差能覆盖成本
  → 检验：过去 7 天的息差还在 > earn 基线？
  → 不是 → 策略退化（前提不再成立——即使当前没亏）

DCI 策略声称：premium > 3×earn
  → 检验：当前 premium 还在这个域？
  → 不是 → 前提塌
```

**NOX 落法**：
- D-576 存活检（funding≥8%）已经在做 carry 族——**泛化为全族**
- 每个模板注册时声明一个 `precondition` 表达式（与②因子表达式共用 DSL）
- armed 评估环每拍同时检查：机会窗口 AND 前提还成立
- 前提塌→自动降仓或暂停（不立即 kill——前提恢复可回来）

**对 ≥8% 的贡献**：提前发现策略失效——不等到亏损了才发现 carry 引擎已死。

## 2. 依赖关系与优先级

```
① 回测引擎（基建——②④⑤ 的验证都依赖它）
   ↓
② 因子组合（策略空间扩大——新组合用①回测验证）
   ↓
③ Regime 检测（独立——不依赖①②，可并行）
④ Kelly sizing（依赖 decision_outcomes 数据积累——已有）
⑤ 前提检验（D-576 泛化——轻量）

推荐建设序：① → {③, ⑤} 并行 → ② → ④
```

| 件 | 建设量 | 对 ≥8% 直接贡献 |
|---|---|---|
| **① 回测引擎** | 中（~2-3 天） | **最高**——迭代速度 ×5 |
| ② 因子组合 | 中（~2-3 天） | 高——策略空间 ×M |
| ③ Regime | 低（~1 天） | 中——少亏 |
| ④ Kelly | 低（~1 天） | 中——资本效率 |
| ⑤ 前提检验 | 低（~0.5 天） | 中——提前发现失效 |

## 3. 禁线（全部五件共用）

- 回测≠免检：paper 闸不撤——回测通过只提升 paper 起点参数质量
- Kelly 是上限建议不是指令：max_gross 硬线（D-030 风控线）不动
- 因子表达式禁 LLM 自动入册：LLM 可建议因子组合（顾问），入册走决策席
- Regime 是降仓/暂停不是 kill：淘汰仍走数学 kill 扳机（D-599）
- 前提检验泛化不改 D-576 既有 carry 族判据：只是扩展到全族
- 全部走 app_config/DB 驱动，禁硬编码

## 4. 与 NOX 既有件的关系

| 既有件 | 升级关系 |
|---|---|
| paper→graduation 管线 | 不动——回测是 paper **前置**（先扫参数再进 paper） |
| app_config 判据表 | 扩为因子表达式字段（②） |
| decision_outcomes 归因簿 | 数据源——Kelly sizing（④）直接消费 |
| kill 扳机（D-599） | 不动——⑤ 前提检验是事前，kill 是事后 |
| D-576 存活检 | 泛化为⑤——全族前提声明 |
| armed 评估环 | 加③ regime 标签读——不适配状态不产机会 |
| fin_opp_hypothesis | params_proto 扩为因子表达式（②） |
