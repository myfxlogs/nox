# 新品类自发现管线设计（决策席草案 · 2026-10-14）

> 命题：venue 上新了系统不认识的产品品类时，管线应能**侦到 → 结构化假设 → 预审备忘录 → 裁决 → 执行或留痕丢弃**——全程业主零动作（透明可见），决策席零在席依赖（备忘录备好等批）。
> 地位：「自我进化」命题的核心管线。钱径六域中本管线横跨 数据（侦测）→ 研究（假设/预审）→ 决策席（裁决）→ 交易（执行）。

## 1. 现状盘点（已有什么件，不新造轮子）

| 已有件 | 能复用的面 |
|---|---|
| universe-radar（每小时 :17） | 已扫全 venue 宇宙目录——**加 diff 即可侦品类新增** |
| explorer + analyst LLM | 已有 LLM 调用基建（产 observed 条目/备忘录同构） |
| `fin_condition_gap` + 请求箱 | 缺口/请求路由现成；`kind` 枚举加值即可（1017 有先例） |
| `paper_spot_carry` 纸面沙箱 | 市场路径型验证全建制（N 轮闸/收敛/毕业链） |
| `carry_graduations` 晋级链 | pending 建议→approve 闸（决策席位）+stale 自过期 |
| `watch_rule` 引擎 | DB 驱动规则+告警径的范式先例 |
| alerts→飞书 | 备忘录推送通道零新件 |
| 通用执行先例 | `goEarn`/`bnapi_earn` 申购赎回已是参数化动作族雏形 |

## 2. 管线五段


```
①侦测   **两级源**（自审实证：universe-radar 只扫合约仪器轴
         SPOT/SWAP——earn/DCI 根本不在宇宙目录，纯 catalog diff
         覆盖不了「系统从未调用过的端点面」）：
         a) **目录内新品型**：在采端点内冒新 instType/新结构字段
            → 目录 diff 产事件（universe-radar 既有径扩 instType 集）
         b) **端点族级新品类**：venue 公告 feed（binance/okx 公告
            API/RSS 为「我没调过的面」唯一覆盖径）→ LLM 读标题
            → 命中收益类关键词产「品类事件」（不是假设，是原料）
            │
②假设   explorer 消费事件：LLM 读 venue 产品描述→产 fin_opp_hypothesis
         结构化行（品类名/venue/参数原型/证据链/status=proposed）
            │
③预审   LLM 备忘录：族归属判定（契约型/路径型/不入族）+参数面映射+
         疑点清单+草案裁决——**只产 memo 不碰批准键**
            │
④裁决   决策席三分叉（备忘录在手，裁决是秒级动作）：
         ├─ 批·装得进通用族 → 参数行入册 → 小额试单径（额度封顶）
         ├─ 批·新机制 → 立施工票建模板/执行器 → 入册后自动
         └─ 丢弃 → 落原因 → 弃件记忆（同签名永不再扰）
            │
⑤执行   契约型：generic_yield 参数面直接试单（现有闸全过：
         risk.Check/额度/幂等）；路径型：paper 沙箱 N 轮→毕业链
```

## 3. 通用族参数面（设计命门）

契约型收益族 `generic_yield`（先立一族，验证范式后扩族）：

```
参面 = {venue, product_id, ccy, tenor_days, apr, min_qty, max_qty,
        redeem_type(flexible|locked|maturity), lock_terms}
采集 = 产品目录读（universe 已有径）
评估 = apr×tenor − 显式费 − 锁期折价（保守常量挂 app_config——
        「对手方折价分」现网零数据源，砍掉不做；
        venue 对手方风险走浓度透视告警面，不进单品评估式）
执行 = 申购/赎回两动作——**每 venue 适配器族**（实证：goEarn 现
        binance 单 venue 写死，S2 含各所 API 适配不是一画就成）
```

**圈界**（D# 定）：契约型固定收益=圈内；含杠杆/期权卖方/锁定>阈值天=圈外（升级新模板径）。圈每扩一次=一条 D#。

## 4. 数据模型（草案）

```sql
fin_opp_hypothesis            -- 新品类假设行
  id, venue, category_key（签名：venue+instType+形态键——幂等锚）,
  params_proto jsonb, family_fit text('generic_yield'|novel|none),
  memo text, status(proposed|approved|rejected|trialing),
  decided_by, decided_at, reject_reason, first_seen, last_seen
```

事件不重发：`category_key` UNIQUE + rejected 行在册即抑（弃件记忆）。
**条款变重推**：抑的是同签名**同档条款**——条款实质变化（APR 档
上移超阈，阈挂 app_config）破例重评，拒件不永眠。

## 5. 三层把关（参数面归属）

| 层 | 谁 |
|---|---|
| schema 字段/校验（工程件） | 施工票常径（实施写+复审并） |
| 能力圈边界（族覆盖到哪） | 决策席 D# 逐扩 |
| 圈外放行/新凭据新资金 | 自动升级请求箱→业主 |

预审 LLM = 顾问：产 memo，**批准键永不在它手里**。

## 6. 噪音与幂等纪律

- 弃件记忆：`rejected` 行在册 → 同 `category_key` 零重推
- 聚合告警：新假设落库推一条 info（含 memo），不重扰；批后小额试单 warn 级留痕
- stale 守卫：目录读败/字段缺 → fail-closed 不产假设（宁可漏不可编）

## 7. 禁线

- 钱径零 LLM（申购/赎回/下单签名记账风控零沾）——LLM 只到「备忘录」止
- 跨 venue 划转系统永不执行（只提案——复用 xfer 票语义）
- 零新 env/凭据；venue 读径败 fail-closed
- 参数面圈外品类**禁强塞**（装不进=新机制径，不挤进 generic_yield）

## 8. 分期（薄→厚）

| 期 | 范围 | 验收 |
|---|---|---|
| **S1 蹭轨版** | 目录 diff→假设行+memo→info 告警；裁决=决策席人工立票 | 造一新增品类→假设行+memo 落库+告警到 |
| **S2 通用族** | `generic_yield` 参数面+**每 venue 申购/赎回适配器族**+圈界 D# | 契约型新品类批后小额试单真成交 |
| **S3 闭环** | 试单→毕业链晋级；弃件记忆全跑通 | 新假设→批→试单→晋级全链零人工 |

## 9. 决策点（留给集中处理）

- D#：generic_yield 圈界第一版（含/不含哪些条款形态）
- D#：S1 假设行的 LLM 预审是否启用（有成本，事件频率低）
- D#：新品类小额试单的额度封顶值
- D#：venue 公告 feed 侦测是否启用（b 级源，覆盖「未调用端点面」的盲区——目录 diff 够不着的那一半）
