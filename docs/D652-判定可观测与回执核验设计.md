### A.2 设计：`internal/platform/rejects` 计数器件

```go
// Key 面=判定面名（常量）；门=拒因名（常量）。
type Key struct{ Face, Gate string }
type Row struct { Key; N uint64; First, Last time.Time }

func Register(face string, gates ...string) // 装配时显式注册（键集静态——热路径零分配，键爆炸结构性防）
func Inc(k Key)                             // 判定点原子 +1（未注册键=忽略+boot 一次 warn=接线漏挂早号）
func Ring(k Key, subject string)            // bounded 256 环形缓冲记最近拒例 subject（诊断面，默认关）
func Snapshot() []Row                       // dump 面（拷贝快照）
```

- **零业务副作用**：只数不判，任何判定结果零变化；
- **热路径成本**：预注册键直读+一次原子加（无 map 增长、无分配）；
- Ring 开关走 env 白名单（bootstrap 域合规，默认关）。

## C. fulfilled 到账核验环（P1·研究域）

### C.1 现状实病

#1937 实证：capital 请求 06:18Z 落箱（okx unified 需 ~1500，三要素齐）→06:30Z 人工标 fulfilled→11:53Z okx:earn 仍 2128.71/unified 恒 $0——回执与实况不符，已批机会（ETH #387）死等，无任何告警。

### C.2 状态机扩展

```
open → requested → marked（人工点击=待到账）→ fulfilled（系统：到账实测）/ waived
```

- 迁移：status 值域增 `marked`；加列 `target_bucket text NULL / target_usd numeric NULL / marked_at timestamptz NULL`（幂等）；
- 请求作曲器：kind=capital **必填** target_bucket/target_usd（三要素已含此信息，落结构化列）；存量行 NULL=legacy 语义（人工 fulfilled 仍合法——仅 capital 新行走核验）。

### C.3 到账核验（事件锚定·零新定时器）

- 搭车 idle_capital_monitor 既有周期：每轮扫 `marked` 行→读 target_bucket 最新快照桶值→**桶值 ≥ marked_at 时桶值 + target_usd×0.95** →系统翻 fulfilled（evidence=前后两快照 id 落行注记）；
- 快照读败=fail-closed 保持 marked；
- `marked` 悬空 >24h → warn 告警「回执悬空」（dedup 24h，告警两级语义合规）；
- boot 一次性清扫：legacy `kind=capital AND status=fulfilled` 行对 target 桶实测——桶值≈请求前值（未到账形）→降 `marked`+告警（如实纠正 #1937 类存量；只降不删，evidence 留痕）。

### C.4 消费面

- 装配/jit/风控：不认 `marked` 只认 `fulfilled`（实际资金判定它们本就直验桶值——零改，状态面为人/面板语义）；
- 前端请求箱：`marked` 显「待到账」态（回执按钮语义=「标记已划」）。

### C.5 验收锚

- 单测：marked+到账注入→系统翻 fulfilled；25h 悬空→warn；legacy 清扫降级锚；credential 类回执径零改锚；
- SG：#1937 复盘三选一实拍——boot 清扫降 marked / 资金实划自动 fulfilled / 悬空告警达飞书。
