# 日历基差提案模板设计（决策席草案 · 2026-10-14）

> 命题：雷达交割轴已产真信号（SG 10-14 实拍：SOL-USD_UM-261030 basis_ann=+19.0%、BTC-USD_UM-261030=+5.8%、binance BTCUSDT_270326=+5.1%、XAU-USD_UM-261127=−10.3%），但**信号到提案之间没有模板**——本稿把「交割腿基差」翻译成可评可验的策略形态。
> 地位：雷达轴投资的兑现件——发现层已建完，此稿是研究层接线设计。

## 1. 策略机制定义

**日历基差 carry**：同一标的的交割合约与永续/现货间价差，随到期收敛至零。

```
basis = mark_fut / index − 1            （现货溢价率）
basis_ann = basis × 365 / days_to_expiry （雷达已有，年化口径）
```

**正向 carry（contango，basis>0）**：
- 空交割腿 + 多对冲腿
- 收益 = 基差收敛（到期归零）
- 到期交割腿自动按 index 结算=收敛保证——**这是和 perp×perp 的本质差别：收敛有截止时间不是漂移**

**对冲腿选型（自审修正——原稿 funding 方向写反了）**：
| 对冲腿 | funding/成本 | 爆舱面 | 资本占用 |
|---|---|---|---|
| **现货**（P0 默认） | 零——无 funding 拖拽 | 长腿无爆舱 | 全额名义（资金效率低但结构最净） |
| 多 perp（P1 变体） | **付** funding（正 funding 期是成本项非收益——实测定 funding 正为主，会啃掉薄基差） | 双腿都挂保证金，爆拉时交割空腿承压 | 保证金制省资本 |

> 原稿「空 perp 腿另收 funding」是 backwardation 构型的腿——本稿 P0 已排除反向，删错位表述。**结论：P0 用现货对冲（binance 现货腿实拍出借面存在），perp 对冲带 funding 成本记 P1**。

**反向（backwardation，basis<0，XAU 实证存在）**：
- 多交割腿 + 空对冲腿——结构对称但做空腿成本不同，P0 不碰（先入册正向）

## 2. 配对构型（设计抉择点）

| 构型 | 例 | 语义 | 裁定 |
|---|---|---|---|
| **同所同结算** | binance BTCUSDT_261225 空 + BTCUSDT perp 多 | 两腿 USDT 结算，零汇兑残差 | **P0 主推**——最干净 |
| **同所跨结算币** | okx BTC-USD_UM-261030 空 + BTC-USDT-SWAP 多 | USDⓈ篮 vs USDT——结算币残差≈稳定币脱锚险 | P1——残差小但真实存在 |
| **跨所** | 空 binance 季度 + 多 okx perp | 基差+所间价差混合，腿失衡险最大 | **不收**——清算/保证金跨所理不顺 |

P0 口径：binance USDT 季度 ×4（BTC/ETH×1225/0326）在同所同币环境跑——**SOL/XAU 的高基差信号（USD_UM）要进 P1 结算币残差条款**。

## 3. 评估式

```
net_ann = basis_ann
        − 双边吃单/挂单费 ×2腿（venue fee 表真值，禁编）
        − 对冲腿 funding 成本（多 perp 时付；空 perp 时收——venue 当期率）
        − 滑点估算（depth 缺→fail-closed 标不可评不编）
        − roll/退出预留（到期前平仓的摩擦成本常量，app_config）
```

fail-closed 沿用雷达惯例：basis_ann/mark/index/fee 任一缺 → 不可评如实行。

## 4. 风控与残差风险（要钉死的）

| 风险 | 实质 | 处置 |
|---|---|---|
| **腿失衡** | 一腿成一腿不成=裸方向 | 成交原子性 venue 管不了→执行侧「未成腿即回滚已成腿」设计（执行票的事） |
| **空交割腿爆保证金** | 暴拉时空腿亏、现货腿赚的=净值中性但**保证金需求是非对称实时的**；现货对冲下爆的总是交割腿 | 保证金缓冲顶+追加通道=执行票评估项 |
| **结算币错配** | USD_UM 结 USDⓈ vs USDT 腿——脱锚时两腿 PnL 币种不一 | P1 才收，条款写明 |
| **到期清算尖峰** | 到期日结算价波动 vs index 差异 | **到期前 T−1 平仓纪律**（不留到 venue 自动结算） |
| **basis 恶化** | 入场后基差转负=浮亏 | 纸面轨先量「入场后收敛路径分布」再定止损界——**这是纸面要产出的证据** |

## 8. 与既有件的关系

- **不复用** paper_spot_carry 的收敛假设——日历基差收敛是**到期保证**不是均值回归，评估语义要分开（structure 新枚举就是干这个的）
- **配对不可复用**（自审实证）：`divergences()` 硬编码 `a.Venue==b.Venue→跳过`+`FundingAnn!=nil` 门槛——FUTURES 行 funding 恒 nil 天然进不了散度对。perp_delivery 需要**新配对接**：同 venue+同 canonical+ct 不同。
- **复用**纸面表/生命周期/事件冷却骨架；**记账式不可复用**——perp_perp 的 accrual 是 funding 差×天数，perp_delivery 是**基差逐轮市值重估**（Δbasis×qty），PnL 引擎要新写。
- **P0 前置数据缺口**（自审实证）：交割腿**无盘口深度源**——ticks/bookTicker 不订交割符号，滑点不可量→fail-closed 会全判「不可评」死锁。P0 需补 binance bookTicker REST 逐符号读（4 个符号低频）或标「mark 价入场+滑点未知」诚实降级，建议前者。
- **不建** 执行器——P2 另行，先纸面把「基差策略在我们数据下的真实收敛路径」量出来再谈钱
