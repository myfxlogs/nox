# 告警→AI 席位自动分诊桥（讨论稿）

> 状态：**讨论中**（2026-10-20 立稿；参与：决策席起草、实施席 devin 讨论、业主观察）
> 一句话：系统告警除飞书外同时推给一个 AI 分诊席位——按告警逐次拉起全新会话，只读诊断→立票→推飞书回执；**不直接处置钱径**。
> 讨论收敛后拆票施工（票拆预案见 §8）；本稿不是施工令。

## 1. 问题与动机

- 现状：告警只到飞书 = **业主是唯一反应终端**。夜间/业主离线时段，error/critical 告警无人看；D-033「系统推、终端决」里的"终端"目前只有人。
- 目标：告警触达后 **分钟级** 有一个 AI 席位完成第一反应——取证、定性、立票、给业主一句可读结论；人回来时票已在、结论已在。
- 非目标（明确排除）：AI 席位直接执行处置（下单/平仓/改仓/改配置）——一切处置仍走票+复审门（§4 职责契约）。

## 2. 形态取舍

| | A. 逐告警触发（**推荐**） | B. 常驻会话 |
|---|---|---|
| 原理 | 告警事件 → 桥接器当场拉起一个全新 `claude -p`（或 devin cli）会话 | tmux 挂永续会话，定时喂告警 |
| 上下文质量 | 每次全新读 STATE/票 → 零漂移 | 会话越滚越钝——跨会话漂移是本仓已实证病灶 |
| 成本 | 只在告警时跑 | 24h 常烧 |
| 可靠性 | 挂了只影响单次，下次照跑 | 会话腐坏/断线=静默失明 |
| 延迟 | 冷启动秒级（告警场景足够） | 即时 |

裁定：**A**。B 的唯一优势（即时）在告警场景无意义；其代价（漂移+烧钱+静默失明）全是本仓已付过学费的病灶形态。

## 3. 架构

```
SG nox-core ──error/critical 告警──▶ POST 本机桥（HTTP，鉴权）
                                        │
                                        ▼
                              桥接脚本逐次拉起 claude -p
                       「告警<原文>发生——按 AGENTS.md 契约分诊，读 STATE 行 X」
                                        │
                          ┌─────────────┴─────────────┐
                          ▼                           ▼
                    只读诊断（SSH/DB/RPC 取证）    立票写 STATE 行
                          └───────────┬─────────────┘
                                      ▼
                          结论+票号推飞书 @业主（回执可见）
```

### 3.1 后端件：告警桥 sink（代码票）

- 落点：`internal/ir/notify` 告警写出层，与 FeishuClient 并列的 `AgentBridgeSink`。
- 触发面：**仅 error/critical 级**（warn 级不拉会话——防烧；可 app_config 调级）。
- 配置：桥地址入 `app_config`（`NOX_ALERT_BRIDGE_URL`，缺=功能静默关闭 fail-closed，不影响飞书主径）；鉴权 token 入 `app_secrets`（`NOX_ALERT_BRIDGE_TOKEN`）。
- 防风暴：同类告警（同文案 hash）**24h 只推一次桥**——复用 `InsertAlertDedup` 同语义；桥侧再串行化（同一时刻至多 1 个会话在跑，排队上限 N=3，溢出丢弃并计数）。

### 3.2 本机桥（运维件）

- systemd 服务（dev 机，非 SG——SG 是生产面不养 AI 会话）监听 localhost/内网 HTTP。
- 收到 POST → 鉴权 → **串行**拉起 `claude -p`（权限收窄：只读命令+写 STATE+飞书发送；**禁 git push/禁部署/禁 docker 写操作**）。
- 会话输出落 `docs/报告/告警分诊/<date>-<alertid>.md`（运行时件面，gitignore）+ 关键结论一行回执飞书。
- 失败回退：桥不可用/claude 失败 → 纯飞书旧径不受任何影响（sink 是旁路非串路）。

### 3.3 职责契约（纪律件）

告警会话=**分诊员**，职责三件：
1. 取证定性：按 `skills/生产取证/` 三通道纪律查实告警真伪与影响面；
2. 立票：真问题→STATE 行（含实证+范围+验收锚）；伪警→经验库 staging 记一条；
3. 回执：飞书推「告警 X=定性结论+票号/无需票」。

禁线：不碰钱径（下单/平仓/改仓/改配置值）；不改代码（改码走票）；不做需要业主授权的动作（部署等仍走授权闸）；会话内凭据零落地。

## 4. 纪律对齐

- **D-033**：触发方向=系统推（告警事件拉会话），非 agent 定时轮询——轮询「到点看 X」是明令禁止形态。
- **D-004 无涉**：告警是事件推送，非业务数据面；桥不产/不缓存业务数据。
- **§7 硬线**：桥失败不得阻塞或降级主告警径（飞书）。
- **单源真相**：分诊结论落 STATE/经验库，飞书只是回执通道。

## 5. 故障模式与防护

| 故障 | 防护 |
|---|---|
| 告警风暴拉起百个会话 | 桥侧 24h 同文案去重+串行队列上限 3+溢出计数上报 |
| claude 限流/挂 | 单告警失败即弃（飞书已有原文），下条告警照常 |
| 桥服务挂 | systemd 自动重启；sink POST 失败=静默计数，不重试不阻塞 |
| 桥地址泄露被滥触发 | app_secrets token 鉴权；仅内网监听 |
| 会话跑飞（越权动作） | 权限白名单收窄+输出全落报告件可审计 |
| 成本失控 | 每日会话数上限（app_config，缺省 20/日，超限纯飞书） |

## 6. 分期

- **v1 最小闭环**：error/critical→桥→claude -p→诊断+飞书回执（不含自动立票，回执里给「建议票面」由决策席复核后立）。
- **v2**：回执格式稳定后放开自动立票（STATE 行写入仍过既有 pre-commit 门）。
- **v3（可选）**：分诊结论质量月度复盘（伪警率/定性准确率）入 digest。

## 7. 开放问题（供 devin 讨论）

1. **runtime 选型**：`claude -p` vs devin cli vs 双轨（按告警域分）？devin 侧有无等效非交互模式与权限收窄面？（devin 请给实测口径）
2. **桥落位**：dev 机 systemd（现案）vs SG host systemd（离数据近但生产面养 AI 会话违直觉）？dev 机断电/离线窗=分诊盲窗，可接受吗（飞书主径无损）？
3. **鉴权粒度**：app_secrets 共享 token 够吗，还是按告警域分 token？
4. **warn 级是否进 v1**：现案不进；若 devin 认为某些 warn 域（如流断连）需分钟级反应，给分级白名单方案。
5. **会话权限面具体清单**：允许的命令白名单逐条列（ssh 只读? psql 只读? curl?）——devin 从实施面给清单。
6. **队列溢出语义**：丢弃+计数 vs 合并 N 条同类为一次会话？
7. **回执落点**：飞书群 vs 业主私聊 vs 两者。

## 8. 票拆预案（讨论收敛后立）

1. **后端 sink 票**：AgentBridgeSink+app_config/app_secrets 两键+去重+限频（机检：mock 桥断言 POST 载荷/去重/失败不阻塞）。
2. **本机桥票**：systemd+spawner+权限收窄+报告件径（验收：真告警端到端一回）。
3. **职责契约票**：告警会话 runbook 落 `skills/告警分诊/`+回执格式（验收：演练告警全流程走通）。
