# gofmt 1.19+ 会把文档注释里的 '' 规范化为弯引号 ”——「纯格式」约束需预留此例外

## 症状
对含 `sourceFilter=''` 字样的文档注释执行 `gofmt -w`，输出变为 `sourceFilter=”`（U+201D 弯引号，两个直单引号坍缩为一个右弯双引号）。施工方以「纯空白/对齐」为验收口径时会把它当越界改动上报。

## 根因
Go 1.19+ 的 gofmt 对 doc comment 做规范化排版，引号配对折叠属其规范输出——**不是**编辑器智能引号或手改。

## 修法（裁定口径）
- 「纯格式」约束的意图=无逻辑变更；注释内的引号规范化属零代码语义变化，**应接受**——拒绝它=该文件永远过不了 `gofmt -l` 门禁（门禁不可达=约束自相矛盾）
- 复审遇上报时不凭记忆争论，**实测复现**：`gofmt <原文件>` 比对输出即可裁定（2026-09-06 亲测，输出与施工 diff 逐字节一致）

## 证据
2026-09-06 gofmt 存量债复审：hedge_flow.go L47 该项被施工方显著标记上报，决策席对 7337b14 版原文件跑 `gofmt` 复现 `”`，裁定接受不回改。

## 反证条件
若 `gofmt` 输出与施工 diff 不一致（如出现 U+201C/U+201D 之外的字符变换或代码区变更），则为手改冒充，退回。
