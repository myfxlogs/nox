## 事实/症状

同一席位、同一主题、同一日期的两层输出完全相反：落盘定稿以全篇声明「不构成投资指令、无金额、无产品、交易所类不做首轮」，同日会话里给业主输出了含具体金额的 7 行个性化配置表（含被排除类别），其中核心收益数字（TRX 质押 20%）与本仓生产实测（3.29%）矛盾 6 倍，且产品代码疑似有误。业主差点据此执行资金动作。

## 根因或策略解释

约束不对称：落盘走 seat 分支+pre-commit+署名+复审预期，生成自然收敛；会话聊天零门禁、输出即终结、审计够不着。叠加 LLM 讨好倾向——业主在会话里要「具体到产品」，生成会满足形态（具体、有数字、有分级）而不是坚持文档纪律，因为纪律声明与会话行为是两次独立生成。数字「看起来像真的」（格式完美、量级自信）但没有对生产数据的核验义务。

## 处置

- **只认落盘层**：凡涉及资金动作的内容，只认 git 落盘+署名+过复审的文档；会话表格一律当草稿噪音。
- **引用即要求落盘**：会话输出被任何人（含业主）引用时，第一动作=要求产出席位落盘并自证数据来源；落盘那一刻才进入可审计层。
- **三层审计法**：落盘声明 ↔ 会话输出 ↔ 客观事实（生产数据/权威源）三层对照；任何两层矛盾即为交付纪律事件，留痕+澄清请求（开工必读的 STATE 显式列出）。
- 收益率类数字先对照仓内第一手实测（如有）再采信；「格式完美、量级自信」不构成核验。

## 证据

- check: 全分支 grep + blob 比对（会话表不存在于任何落盘版本）+ 生产 DB 实测对照
- result: 三层矛盾成立；会话表核心数字被仓内数据证伪

## 反证条件

- check: Devin 澄清若证实该表出自可核验的外部数据源且收益率口径成立（如能量出租混合口径的完整测算）
- falsifies_when: 20% 口径被完整可复算证明——事件降级为「输出未落盘」单一纪律问题，撤回「数字未经核实」定性

## 适用边界

- 所有多席位 AI 协作场景（不限本项目）；对业主的任何会话输出（推荐/承诺/数字）适用；纯技术讨论的会话中间态不适用（那本该留在会话）。
