# 开工指令=指针单行，票面细节禁抄进提示词

## 症状

10-22 决策席 D-663 复审收口后出返修提示词，把六条缺陷清单（阻断②残④逐条）全抄进提示词本体；业主纠偏「不是一行提示词？」→ 出单行版 → 业主再纠「但你总忘记出 1 行提示词」=**跨会话复犯实证**。缺陷清单此时已落 STATE 文末注记块——提示词复抄=同一内容 chat/档库各存一份。

## 根因

- boot 协议强制：实施席开机必读 STATE 本行（+注记块锚）——**票面是上下文唯一真相源，提示词是领票钥匙不是票**。提示词抄细节不产生任何协议价值：读 STATE 的义务不因提示词详细而豁免。
- 复抄的直接代价：①细节双份耗 token（票面+chat 各一遍）；②票面单源被稀释（两边不一致时以谁为准）；③票文广播件（TICKETS.md）行亦被撑肥。
- 反例边界：仅「票面外无的信息」落提示词——如分支名未写进票行、临时口令、会话即毁的上下文。

## 修法（出指令侧）

1. 提示词恒=`[角色:实施|复审|决策] <一句话目标>（读 STATE 本行[+注记块锚][+skills/<venue>-<域>|无 skills 域]）`——单行即止。
2. 需要传达的细节先落票面/注记块，提示词只给锚（行号/注记日期/注记块标题）。
3. 自检：提示词里出现第二条缺陷描述/第二步指令=超标，砍回指针形。

## 证据

- 复犯实证：10-22 D-663 返修指令两轮纠偏（对话在案：长版→「不是一行提示词？」→单行→「总忘记」定性）。
- 契约源：AGENTS.md §3 开工指令格式条+§4 票文广播件条（上下文在票不在聊天）。
- 同族先例：prompt-lifecycle-must-anchor-code-position（提示词侧病灶族——细节该给锚而非给文）。
