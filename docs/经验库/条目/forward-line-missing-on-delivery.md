## 事实/症状

决策席完成交付物（互审回行「反：」块、复审结论「复审：」块、返修提示词）落盘 commit + push 后，**未附单行转发提示词**，业主须重复追问才补。

同一会话内两次发生（D-388 R0 回行、D-389 R0 复审结论），业主两次点名「第2次犯规」。

## 根因或策略解释

- **表层根因**：规则只写在私有记忆与 `practices.md` 正文里，没有门禁。记忆是给判断用的，判断会漂——两次都是「写完 commit 就以为交付完成」。
- **深层根因**：本席把业主立的指针交付律（`content-first-forward-as-pointer`）读窄了。业主批评的是「把 D-386 门禁的完整检查逻辑与盲区论述写进对话正文」——**批评字数膨胀，不是内容缺失**。本席修正过度，把「不复述正文」执行成「不携带内容」，然后当成规则照做。结果交付给业主的是「结论=返修，禁派施工」一句话加三个文件路径，业主读完仍要自己去文档里找那一行——**转发行必须是可粘贴即用的**。
- **规范层缺口已补**：D-384 v3 已把「互审回行须附转发行」固化入 `practices.md`；本条目的增量是**把它变成机检**。
- 判据细化：允许进转发行=一行指令 + 关键执行约束（串行要点、R1-Rn 编号、锚编号、停手条款）；禁止=复述正文论证、展开证据链、写异议理由。

## 处置

1. **转发行是「交付完成」的定义，不是交付后的附加动作**：交付 = 仓内正文 + **同一 commit 内的转发行**，不之后补。让「忘了发」在 git 层面不存在。
2. **pre-commit 7f 强制**（D-390）：暂存区含 `docs/*.md` 新增块（`## 反：`/`## 复审：`/`### C. 未收敛项`/`### 返修清单`）**或** `STATE.md` 状态符翻转（🔄/✅/📋），且 commit message + 暂存新增行中均无 `[角色:` 起首行 → 拒提。
3. 与 D-386 正交不合并：D-386 挂 pre-push（丢盘发生在 commit 前，pre-commit 兜不住）；本条目挂 pre-commit（转发行属于 commit 内容，pre-commit 恰是正确挂点）。
4. 绕过口子 `ARBCOMMIT_ALLOW_NO_FORWARD=1`，仅用于纯错别字/格式修正等非交付类改动。

## 证据

- check: 新增含 `## 反：Claude 席` 块的文档 + `git commit`（不带转发行）
- result: exit 1，stderr 含「交付需含单行转发行」+ 补法提示
- ref: D-390 验收锚 A/B/D/E，2026-09-22

## 反证条件

- check: 同一 commit 内追加 `[角色:决策] docs/... @<hash>｜结论=...｜...` 一行
- falsifies_when: 该 commit 仍被拦 → 7f 误伤，说明「转发行属于交付」被判为「转发行不是交付」

## 适用边界

- 「先正文 commit、后转发 commit」形态**无法检出**（7f 只看本 commit）——本条目接受该盲区并明写：该形态本身即 D-390 禁止项，绕过等价于业主手动转发，风险由业主知情承担。
- 纯文档改动且无新增块、无状态符翻转→不触发，正确。
