# NOX 公司架构（v3 · 2026-10-13 · D-246 决策席审计裁定）

> 品牌三层（D-638 补定，业主令 10-20）：**名=NOX**（拉丁「夜」=工作时段）· **神=夜枭**（emblem 层=夜里猎手的本尊，落登录页/投资人页 emblem、报告落款章、名册「夜班枭编制」称呼）· **语=money never sleeps**（副标=D-286 主题）。定名谱系：业主「量子基金/特斯拉」式典故要求→「金钱不眠」主题亲定→Noctua（夜枭）太长→砍三字母词根 =nox（夜本身，非 noctua 截短）。改名不翻案（两裁负收益）。

> 性质：**编制依据**。v2（2026-10-12，D-212）经本席审计后**结构性修订**：保留其核心对象/钱的旅程/三条红线/LLM 判定线，推翻其「十一部 × 员工 × KPI × 部报」的公司隐喻层。v2 原文见 git 历史（`4416af2f` 及之前）。
> 与 `AGENTS.md` 冲突以 AGENTS.md 为准。
> 原则：**边界=写权，不=部门；人数=0；一切面向投资人的东西只有两类——请求与报告。**

## 0. 一句话

NOX 是一家**全自动基金管理公司**：投资人出钱、给条件；系统枚举机会、验证经济性、沙箱试跑、配置资金、原子执行、看护平仓、单源记账、逐仓复盘、自动淘汰。需要人的事只有两类：**向投资人的条件/资金请求**与**投委会的 D# 裁定**。

## 2. 两方契约（投资人 ↔ 基金管理人）

| 条款 | 投资人 | 基金管理人（系统 + 决策席） |
|---|---|---|
| 出资 | 提供资金基数（$10k，D-030）；响应**资金请求** | 资金只认 venue 实读（`capitalview.Live`） |
| 条件 | 响应**条件请求**；回答只有「已满足 / 拒绝 / 需说明」 | 缺口必须显式提请求、禁静默（D-184）；请求含三要素「解锁哪条机会 / 预期净 APR / 占用多少资金」；**请求前做可行性预检**（占用 ≤ 资金基数×单策略上限、venue 在能力账本内），不可行→模板休眠+原因，不发请求 |
| 方向 | 硬线数值、凭据与权限条款（D-594：方向锚、真金动用移交投委会） | 方向锚 · 真金动用 · 其余一切（组织、路线、工具、口径）决策席 D# 全权 |
| 收益 | 「≥8% 净年化是最低益利线，不是承诺」 | D-013 单源口径汇报，口径不随结果调整 |
| 风控 | 不干预个别交易 | 硬线高于目标，系统自动执行（D-032） |
| 透明 | NAV、在仓、请求箱、决策链 | 每笔钱可由 D# → 提案 → 仓 → 账本 → 判决书回放 |
| 退出 | 随时全停/撤资 | KillSwitch / 平仓→结算→报告 |

**投资人接触面硬规则（D-247）**：
1. 到达投资人的消息只有两类：**请求**（条件/资金，三要素+预检通过）与**报告**（周报/事故/NAV）。
2. `fin_condition_gap.kind` 白名单 = `credential | permission | capital | constraint | holding`；**`runtime` 禁止**——系统病灶走 alerts + STATE 票，不进请求箱。
3. 任何 LLM 输出不得含「建议业主…/业主面…」类句；入行前 scrub 拦截。
4. 本稿改动不需业主明示（v2 §12 废止）；业主域收窄=出资/撤资、硬线数值、凭据/权限条款（D-594：方向锚、真金动用移交投委会）。

## 3. 治理层

```
投资人 ── 出资 · 条件 · 硬线数值 · 凭据权限 ─────────────┐
                                                       ▼
投委会（决策席）── 方向锚 · 真金动用授权 · 策略首次真金/淘汰复核 · 预算框架 · 硬线解除 · 探针批准 · D#
   ├─ 实施席 / 复审席 ── 改代码 · 机检 · 合并 · 部署（不进钱径，不裁投资）
   └─ 门禁 ── pre-commit 10 道 · 实施≠复审 · import 红线 · LLM 四铁律
                                                       │
系统（7×24）── 钱径六域 + 平台横切 + 一个判断工作者 ── 只向上输出「待决策」与「请求」
```

决策权矩阵沿用 v2 §2 原表（开户/条件=投资人；模板入册、首次真金晋级、探针、硬线解除=投委会；其余全自动），D-594 修订：**方向锚变更、真金动用授权亦归投委会**——投资人域=出资/撤资、硬线数值、凭据/权限条款；组织/路线/口径类决策=投委会 D#。

### 4.2 平台横切（非部门：无 KPI、无日报、无决策权）

`internal/platform` `internal/infra` `internal/ir` `internal/api` `internal/store` `scripts/hooks`：配置/凭据、HTTP/RPC、推送与投资人页、调度/健康/备份、门禁。daemon 台账标签统一「**平台**」。

### 4.3 一个判断工作者（LLM）

判定线=离钱径距离：思考类可用，钱径类永不（下单、签名、记账、风控、采集）。

- **一个 client**（`platform/analyst`）+ **角色注册表**（prompt + 输出 schema）：研究员（已有 explorer）、评估员（叙事与风险清单，数字归 Go）、复盘员（死因分类）、分析员（飞书应答，已有）、日报（综合）、听证（策略淘汰多空对辩，D-249①——仅观察面不翻裁定）。不建 N 个 agent，agent 不互聊，DB 行是总线。
- **调用账本 `fin_llm_call`（新）**：role/model/tokens/usd_est/ms/ok 逐次落行；月费用进 D-013 费用口径——LLM 对 8% 负责。
- **公司日报=1 次调用**（取代 11 部报+经理摘要 12 次）。输入由 Go 拼、**money-first 固定序**：NAV 与闲置资金比 → 在仓与 carry 实收 → 待决提案（含 age）→ 请求箱（投资人侧 / 系统侧分列）→ 策略态变 → 事故与硬线 → 流健康。不含名册段。
- **系统必算指标（取代 v2 的 11 部 KPI，全部 Go 算、入日报、越线即 alert）**：① NAV 与 30 天净额 vs −3% 硬线距离；② 闲置资金比（未配置 / 基数）；③ 提案滞留中位时长（proposed→终态）；④ 请求箱投资人侧最老 age；⑤ 评估卡预估净 APR vs 实际中位偏差；⑥ 月 LLM 费用 / 月净额。六个数以外的「指标」不进设计稿。
- 四铁律不变：失败落 warn、输出过 schema、无 git/DB 直写、数学归 Go。

### 4.4 运行面台账（原「花名册」）

`fin_employee_registry` 表名不改，**语义改为 daemon 台账**：`Register` 显式入册（装配点）；`Beat` 只 UPDATE 不 INSERT（未登记心跳=一条聚合 warn，非一行员工）；WS ping/keepalive/按账户展开的子循环**不入册**（属某 daemon 的内部节拍）；不搬族尸体行删除。Dept 标签收为 7：`数据/研究/投资/风控/交易/账本/平台`（迁移映射：运营→研究、复盘→账本、IR/运维/合规→平台）。前端页名「运行面」。**在册实拍（SG 2026-10-16）=6 部门 83 席**：数据 23 / 账本 16 / 平台 15 / 交易 14 / 风控 9 / 研究 6——`投资`标签枚举在册但零实体登记（其域职能=armed 闸评估环/提案轨，寄生其他部 daemon 无独立实体）。**人数=0**原则不变——83=daemon 席位编制非人类员工。

## 6. 一笔钱的旅程（主流程与闸，沿用 v2，负责域更名）

| 步 | 名称 | 域 | 闸 / 判据 | 产出 |
|---|---|---|---|---|
| G0 | 枚举 | 研究 | 市场挂牌物 × 持仓合成物 全模板枚举 | watchlist、facts |
| G1 | 匹配 | 研究 | 条件满足→提案；缺条件→**预检后**请求（禁静默、禁 runtime） | `fin_proposal` / `fin_condition_gap` |
| G2 | 经济学验证 | 研究 | 净 APR 五项拆解，任一无证据→不可评估（788% 类直接拦） | `fin_opp_eval` |

| G4 | 晋级 | 投资 → 投委会 | 判据表满足→推「可晋级」；首次真金=投委会翻开关；**提案 SLA** | `fin_strategy` + D# |
| G5 | 配置 | 投资 | 边际净 APR/占用排序；储备、权益纪律、集中度 | `fin_strategy_budget` |
| G6 | pre-trade 风控 | 风控 | 单入口；残腿/事故/权益/预算一致/市窗/财历 全 fail-closed | 放行票据 |
| G7 | 执行 | 交易 | 多腿原子、MT 先行、maker 单腿、LEGGED 即回滚 | positions/legs |
| G8 | 看护 | 交易 + 风控 | 收割/止损/carry 失联/灾难带/CLOSING 超时升级 | 平仓 |
| G9 | 结算 | 账本 | 单源净额、completeness、NAV 日切 | settlements、`fin_nav_daily` |
| G10 | 复盘 | 账本 | 判决书、预估 vs 实际回写 G2 | `position_reviews` |
| G11 | 淘汰/升级 | 投资 | 硬判据自动；投委会月复核可反裁 | `fin_strategy` 态变 |
