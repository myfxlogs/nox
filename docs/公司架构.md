> 性质：**编制依据**（业主 2026-10-12 全权授权决策席，D-212 裁定生效）。此后组织/代码/票以本稿为纲；搬迁裁决面=`docs/搬迁清单.md`。
> 与 `docs/公司编制.md`（v1 审议稿）关系：v1 是「现有 daemon 按部门归档」的盘点；本稿是从基金公司第一性出发的全新设计，v1 的部门盘点、LLM 四铁律、差距表作为素材吸收，批准后 v1 并入本稿或归档。

> 原则：**部门=职责边界，不=人数**。$10k 基金不养人，每个部门落地为一组 Go 包 + 它独占写权的 PG 表 + 一条机器可读的输入/输出契约。

## 0. 一句话

ARB Capital 是一家**全自动基金管理公司**：投资人出钱、给条件；公司枚举机会、验证经济性、沙箱试跑、配置资金、原子执行、看护平仓、单源记账、逐仓复盘、自动淘汰，并把一切需要人的事压缩成两类——**向投资人的条件请求**与**投委会的 D# 裁定**。

## 1. 两方契约（投资人 ↔ 基金管理人）

| 条款 | 投资人（业主） | 基金管理人（系统 + 决策席） |
|---|---|---|
| 出资 | 提供资金基数（现 $10k，D-030）；响应**资金调用**（划转/入金） | 不得擅自假定资金存在；资金只认 venue 实读（`capitalview.Live`） |
| 条件 | 响应**条件请求**（开户/凭据/权限/约束喂入）；回答只有「已满足 / 拒绝 / 需说明」 | 条件缺口必须显式提请求，禁静默跳过（D-184）；请求必须说明「满足后解锁哪条机会、预期净 APR、占用多少资金」 |
| 方向 | 持有方向锚修改权（§1）、真金动用总闸（资金基数、硬线数值） | 方向锚内一切投资决策全权（D-030/D-066） |
| 收益 | 接受「≥8% 净年化是最低益利线，不是承诺」 | 以 D-013 单源账本口径汇报；汇报口径不得随结果调整 |
| 风控 | 不干预个别交易 | 风控硬线高于收益目标，硬线由系统自动执行（D-032） |
| 透明 | 任何时刻可看：NAV、在仓、请求箱、决策链 | 每笔钱的旅程可从 D# → 提案 → 仓 → 账本 → 判决书回放 |
| 退出 | 可随时要求全停/撤资 | 全停=KillSwitch 路径，撤资=平仓→结算→报告 |

**投资人接口只有一个：IR 门户**（§4.8）——飞书推送 + 前端「投资人页」。投资人不看盘、不下单、不读日志。
**接触面硬约束**：发现 / 验证 / 纸面三段零投资人接触（业主令 2026-10-11）。

## 2. 治理层

```
投资人 ── 出资 · 条件 · 方向锚 ─────────────────────────┐
                                                        ▼
投委会（决策席会话）── 策略准入/晋级/淘汰复核 · 预算框架 · 硬线解除 · 探针批准 · D# 留痕
   │
   ├─ 技术委员会（实施席 / 复审席）── 改代码 · 机检 · 合并 · 部署（不进钱径，不裁投资）
   │
   └─ 合规与审计（门禁 + 契约）── pre-commit 10 道 · 实施≠复审 · LLM 四铁律 · 决策必 D#
                                                        │
公司（系统，7×24）── 十个业务部门（§3/§4）── 自动运行，只向上输出「待决策」与「请求」
```

### 决策权矩阵

| 决策 | 投资人 | 投委会 | 系统 | 留痕 |
|---|---|---|---|---|
| 资金基数 / 出资 / 撤资 / 跨 venue 划转 | **决定并执行** | 提请求（含用途与预期） | 生成请求、验证到账 | 请求行 + D# |
| 开户 / 凭据 / 权限 | **执行** | — | 生成请求、探活验证（D-188） | `fin_condition_gap` |
| 方向锚 / 硬线数值 | **明示** | 起草 D# | 执行 | D# |
| 模板入册 / 停用（产品目录变更） | — | **裁定** | 提案（研究部） | 迁移 + D# |
| 策略晋级 纸面→小额真金（首次真金） | — | **翻开关** | 判据满足自动推「可晋级」 | D# |
| 策略晋级 小额→常规、常规内扩仓 | — | 复核（月） | **自动**（预算框架内） | 预算行 |
| 策略降级 / 淘汰 / 休眠 | — | 复核、可反裁 | **自动**（硬判据） | `fin_strategy` 态变 + D# |
| 策略级资金预算 | — | 设总框架（储备比例、单策略上限） | **配置器自动分配** | `fin_strategy_budget` |
| 单笔开仓 / 平仓 / 加减仓 | — | — | **全自动** | positions/legs |
| KillSwitch 触发 | — | 解除 | **自动触发** | execution_control_events |
| 探针（真金取证） | — | **D# 批准**（D-046 边界） | LLM 提案、代码执行 | explorer_proposals |
| 代码变更 | — | 立票 | — | STATE + 实施/复审 |

## 3. 组织架构

```
                       ┌──────────── 前台（找钱、下单） ────────────┐
                       │ 研究部 → 投资部（组合管理） → 交易部         │
                       └──────────────────┬──────────────────────┘
 中台（独立制衡）        风控部 ─┤  运营部（能力与条件）
                       ┌──────────────────┴──────────────────────┐
                       │ 后台：清算账本部 → 绩效复盘部 → 投资者关系部  │
                       └─────────────────────────────────────────┘
 支持                   数据部（可观测世界）   技术运维部（在线与考勤）   合规审计（门禁与留痕）
```

**三条独立性红线**（制衡靠结构，不靠自觉）：
1. **风控独立于投资**：风控部的闸是 pre-trade 必经且 fail-closed，投资部/交易部不得绕过，参数不由投资部写。
2. **账本独立于交易**：账本只认 venue 回执与现金流，交易部不能写 realized；统计/淘汰/汇报三消费者同一函数（D-013）。
3. **研究独立于执行**：研究部产出的是提案与判决书（账本行），永远没有下单工具；执行只消费经过投资部配置、风控放行的行。

## 4. 部门职责

每部门：使命 · 输入→输出（独占写权的表）· 决策权 · KPI · 复用 / 新建。
「复用」栏按**消费者**列（谁用），**代码位置以 `docs/搬迁清单.md` §1 为准**（谁拥有）——如 `symdig`/`analyst`/`combo` 由研究/复盘部消费但落 `data`/`platform`（清单 §11 Q6）。

### 4.1 研究部（Research）
- **使命**：回答「世界上有什么机会、我们能不能做、值不值得做」。产出必须是**带判决书的候选**，不是机会行。
- **输入**：facts/quotes（数据部）、能力账本（运营部）、模板册。
- **输出**：`fin_opp_template(+_cond)`（产品目录，变更走迁移+D#）、`fin_proposal`（提案）、`fin_condition_gap`（缺口）、**评估卡**（新：`fin_opp_eval`——净 APR 拆解、置信、风险清单、失败模式）、研报（`docs/研究/`）。
- **决策权**：无执行权；可提「模板入册」提案给投委会。
- **KPI**：有效提案率（提案→晋级 / 提案总数）、缺口关闭率、评估卡覆盖率（无评估卡的候选 = 0）。
- **复用**：`universe-radar`（全宇宙枚举）、`carry-universe`/`xasset-monitor`/`detector`/`scan`（信号）、`oppmatch`（模板×账本匹配）、`explorer`（LLM 研究员）、`symdig`、`evaluator`（三档判定雏形）。
- **新建**：**经济学验证器**（§6 G2，`internal/econ` 升格为模板级：毛收益 − 费率事实 − 滑点（`fin_cex_depth`）− 失败成本（历史 LEGGED 率 × unwind 成本）− 市窗损耗；任一项无证据 → fail-closed「不可评估」而非默认值）；评估卡表与 LLM 评估员（叙事与风险清单，数字归 Go）。

### 4.2 投资部 / 组合管理（Portfolio Management）
- **使命**：掌管**策略生命周期**与**资金配置**——决定哪条策略在哪个阶段、拿多少钱、什么时候升降级。
- **输入**：评估卡、纸面成绩、账本统计、风控框架（投委会设）。
- **输出**：**`fin_strategy`**（新：策略生命周期状态机，§5）、**`fin_strategy_budget`**（新：策略级 NAV 预算、储备、上限）、晋级/降级事件（alerts「待决策」）。
- **决策权**：预算框架内自动配置与升降级；首次真金晋级只能推「可晋级」待投委会翻开关。
- **KPI**：组合净年化 vs 8%、资金利用率（已配置/基数）、储备达标率、策略集中度。
- **复用**：`strategy_stats`、`carry_graduations`（毕业链雏形）、`xasset_allow_combos`/`fin_venue_exposure_caps`/`fin_canonical_exposure_caps`（现有 cap 退化为配置器输出的 venue 侧投影）、`capital_accounts`/`capital_decisions`/`capital_snapshots`（NAV 骨架）、`live_gates`/`execution_controls`。
- **新建**：**资金配置器**（`internal/allocator`：按「边际净 APR / 占用保证金」排序分配，硬约束=储备 ≥30% 不常驻、CEX 权益 ≥35% / CFD ≥25% 名义、单策略 ≤ 上限、相关性桶（同标的同方向视同一桶）；输出预算行，闸层只认预算行）；**晋级闸**（纸面毕业判据机读：存活时长、accrued>0、净额置信下界（`internal/mmm`）、零 fail-closed 行；判据不满足则「不可晋级」显式列原因）。

### 4.3 交易部（Trading / Execution）
- **使命**：把一张已配置、已放行的订单意图变成多腿原子成交，并对任何半成品负责到底（收平或升级告警）。
- **输入**：投资部放行的执行意图（含预算行 id、提案 id）、风控 pre-trade 放行票据。
- **输出**：`positions`/`position_legs`（腿级取证含 `fail_reason`/`submitted_at`，D-208）、venue 订单回执、执行质量事件（滑点、fill_kind、LEGGED）。
- **决策权**：执行细节（maker/taker、腿序、重试次数）；**无**开仓与否的决策权。
- **KPI**：LEGGED 率、实际往返成本 bps vs 评估卡预估、半平裸奔时长、拒单归因覆盖率。
- **复用**：`exec`（MT5/CEX 执行器、maker 序列 D-018、腿量匹配 D-026、MT 先行序 D-084）、`autotrade` pipeline、`engine`、`dciexec`（DCI 轨）、`reconcile/auto_close`。
- **新建**：执行质量回写评估卡（预估 vs 实际，反哺经济学验证器）。

### 4.4 风控部（Risk）
- **使命**：独立的 pre-trade / post-trade 闸与硬线执行者。宁可不做，不可做错。
- **输入**：订单意图、在仓、venue 权益实读、账本 30 天净额、事故仓状态。
- **输出**：放行/拒绝票据（带原因，可回放）、KillSwitch 事件、硬线告警。
- **决策权**：拒绝权绝对；放行只是「不反对」。参数来自投委会 D#（app_config），非投资部。
- **KPI**：硬线零穿透、fail-closed 误拦率（有记录可审）、事故仓归档时长。
- **复用**：`autotrade.Gate`（残腿闸 D-015、事故闸、权益纪律 D-032、dd30 KillSwitch）、`position.Monitor`、`selfwatch`、`dephealth`、`mtHealth`、`acctMon`。
- **新建**：**pre-trade 单入口**（所有执行轨——xasset/funding/DCI/未来模板——必经同一 `risk.Check(intent)`，禁各轨自带闸）；**预算一致性闸**（意图名义 ≤ 预算行余额）；post-trade 日切（NAV、敞口、集中度三面）。

### 4.5 运营部（能力与条件 · Operations）
- **使命**：维护「我们有什么」的机器可读账本，并把「缺什么」变成对投资人的请求、把「已满足」自动核销。
- **输入**：`broker_accounts`/`exchange_configs`/凭据有无、权限探活、持仓/余额实读、投委会裁定（休眠、约束）。
- **输出**：能力账本投影（`ListCapabilityLedger`）、`fin_capability_constraint`、`fin_capability_permission`、`fin_condition_gap`（requested/fulfilled 态机 + 自动收口与复开，D-193）。
- **决策权**：无投资决策；约束行写入须有出处（业主令或 D#）。
- **KPI**：假缺口数=0、缺口平均关闭时长、账本↔现实漂移告警数。
- **复用**：D-186/D-188/D-193 全部；`symbol_map`/`broker_symbol_map`/`asset_equiv`（品种宇宙）。
- **新建**：**资金请求 kind**（缺口表新增 `capital:<venue>:<usd>` 类——资金调用与凭据请求走同一箱、同一态机）。

### 4.6 清算账本部（Fund Accounting）
- **使命**：唯一真相的钱账：每腿成交、每笔现金流、每仓结算、每日 NAV。
- **输入**：venue 回执与私有流（成交/资金费/swap/利息/交割）。
- **输出**：`position_cashflows`、`position_settlements`、`income_events`、`position_daily_income`、`capital_snapshots`（NAV 日切）、`fin_dci_order` 终态。
- **决策权**：口径权（净额 = 价差 + funding/swap − 全部费用，D-013）；不改历史行，更正走冲销行。
- **KPI**：结算 `applied` 率、两真相事件=0、NAV 日切零缺。
- **复用**：`settlement`、`reconcile`、`swapledger`、income 采集、D-013 单源函数、D-207 DCI 交割。
- **新建**：**NAV 日切**（基数 + 已实现 + 未实现 + 闲置，按 venue 实读；给 IR 与配置器同一数）。

### 4.7 绩效复盘部（Performance & Review）
- **使命**：每个 CLOSED 仓都要有**判决书**；每条策略都有可信的统计；淘汰与升级有证据。
- **输入**：账本、腿级取证、funding/regime 事实、评估卡（预估）。
- **输出**：`position_reviews`（扩：死因分类 + 判决 + 预估 vs 实际偏差）、`strategy_stats`（置信界、依赖性、`hpr_bps` 资本效率，D-180/D-181）、周报/月报数字段。
- **决策权**：淘汰扳机的证据供给；扳机本身由投资部状态机执行。
- **KPI**：判决书覆盖率 100%、预估偏差中位数、淘汰误杀复盘数。
- **复用**：`review`（deviation_bps 归因雏形）、`mmm`（统计）、`sysretro`、`settlement_elim`、`analyst`（LLM 叙事）。
- **新建**：**复盘员**（事件驱动：CLOSED → Go 拼事实段 → LLM 分类死因与建议 → 判决书行 → 统计消费；#510 六连亏靠业主来问才解剖，这是该岗存在的实证）。

### 4.8 投资者关系部（IR）
- **使命**：公司对投资人的**唯一接口**。把内部一切翻译成三样东西：报告、请求、确认。
- **输入**：NAV、在仓、缺口/资金请求、待决策项、事故。
- **输出**：飞书推送（周报/日报/事故/请求）、前端「投资人页」（NAV 曲线、在仓、请求箱、决策链）、投资人回执落账（请求态机）。
- **决策权**：无。只做翻译与送达；文案须含「解锁什么 / 预期多少 / 占用多少」三要素。
- **KPI**：请求响应时长、报告准点率、投资人追问数（越少越好——追问=报告没说清）。
- **复用**：`notify`（飞书）、`selfwatch`（周报/日报/就绪报）、`feishu_query`（分析员应答）、D-200 持仓/提案面、D-189 口令径。
- **新建**：投资人页（只读 + 请求箱回执按钮）；报告模板统一三要素。

### 4.9 数据部（Market Data）
- **使命**：可观测世界——所有 venue 的报价、费率、规格、账户、持仓、终态事件，以流为唯一正道（D-004）。
- **输出**：`facts`、`ticks`、quotes bus、`cex_private_events`、`fin_venue_account_snapshot`、`trade_session`、`macro_event`。
- **纪律**：venue 原生值不编造；无流举证才低频拉且只作统计/复盘；订阅集=研究产出 ∪ 公共兜底（防「评不上就没数据」自证死，v1 §2）。
- **复用**：`collect`、`adapter`、`cexscan`、`macro`、`fact`、`venue`。

### 4.10 技术运维部（Infra & Ops）
- **使命**：公司 7×24 在线、员工考勤真实、数据有备份、部署可回滚。
- **输出**：`fin_employee_registry`（考勤，D-190/D-211）、健康探针、备份三落点（D-110）、部署记录。
- **复用**：`safego`、`sched`、`dephealth`、egress-probe、backup/cron。

### 4.11 合规审计（Compliance）
- **使命**：决策可追溯、代码可审、agent 不越界。
- **规则**：决策必 D#；实施≠复审；pre-commit 10 道；LLM 四铁律（失败落 warn、输出过 schema、无 git/DB 直写、数学归 Go）；钱径零 LLM。
- **复用**：`scripts/hooks`、`decisions.md`、`STATE.md`、经验库。

## 5. 核心对象（部门间契约 = 账本行，不走对话）

| 对象 | 表 | 写权 | 读者 | 状态机 |
|---|---|---|---|---|
| 机会模板 | `fin_opp_template(+_cond)` | 研究部（迁移+D#） | oppmatch、评估器 | active / dormant（约束行 D-204） |
| 能力账本 | `fin_capability_*` + 投影 | 运营部 | oppmatch、配置器、风控 | — |
| 条件/资金缺口 | `fin_condition_gap` | 运营部 | IR、oppmatch | requested → fulfilled ⇄ reopen |
| 提案 | `fin_proposal` | 研究部 | 投资部、IR | proposed → executed / expired / declined / deferred |
| **评估卡**（新） | `fin_opp_eval` | 研究部 | 投资部、复盘部 | 一提案一卡；执行后回写实际 |
| **策略**（新） | `fin_strategy` | 投资部 | 风控、交易、复盘、IR | 见下 |
| **预算**（新） | `fin_strategy_budget` | 投资部（配置器） | 风控闸、交易 | 日切重算 |
| 持仓/腿 | `positions`/`position_legs` | 交易部 | 全部 | OPENING → OPEN → CLOSING → CLOSED（LEGGED/FAILED 事故支） |
| 现金流/结算 | `position_cashflows`/`position_settlements` | 账本部 | 统计、风控、IR | pending → applied / partial |
| 判决书 | `position_reviews` | 复盘部 | 投资部、IR | 一仓一书 |
| NAV | `capital_snapshots` | 账本部 | 配置器、IR | 日切 |
| 决策 | `decisions.md` D# | 投委会 | 全部 | 追加不改 |

**策略生命周期状态机**（投资部独占写；每次迁移写事件行 + 判据快照）：

```
idea ──评估卡齐──▶ paper ──毕业判据──▶ probe/pilot（小额真金，需投委会翻开关）
                                            │ 账本置信 ≥ 线 ∧ 零事故
                                            ▼
          retired ◀──硬判据──  live ──▶ degraded（预算减半、停新开）──▶ live / retired
          dormant（投委会裁定，约束行承载，行删即复活）
```

毕业/晋级/降级/淘汰判据全部机读、全部在判据表里，禁代码字面量（D-191R9 口径）。

## 6. 一笔钱的旅程（主流程与闸）

| 步 | 名称 | 负责部门 | 闸 / 判据 | 产出 |
|---|---|---|---|---|
| G0 | 枚举 | 研究部（universe-radar、采集订阅） | 市场挂牌物 × 持仓合成物 全模板枚举 | watchlist、facts |
| G1 | 匹配 | 研究部（oppmatch × 能力账本） | 条件满足 → 提案；缺条件 → 缺口请求（禁静默） | `fin_proposal` / `fin_condition_gap` |
| G2 | 经济学验证 | 研究部（验证器 + 评估员） | 净 APR = 毛 − 费 − 滑点 − 失败成本 − 市窗损耗，任一无证据 → 不可评估 | `fin_opp_eval` |
| G3 | 纸面沙箱 | 研究部/投资部 | 以同一验证器记账的纸面行；存活、accrued、fail-closed 行数 | paper 表 |
| G4 | 晋级 | 投资部（晋级闸）→ 投委会 | 判据表满足 → 推「可晋级」；首次真金=投委会翻开关 | `fin_strategy` 态变 + D# |
| G5 | 配置 | 投资部（配置器） | 边际净 APR/占用排序；储备、权益纪律、集中度、单策略上限 | `fin_strategy_budget` |
| G6 | pre-trade 风控 | 风控部（单入口） | 残腿/事故/权益/预算一致/市窗/财历 全 fail-closed | 放行票据 |
| G7 | 执行 | 交易部 | 多腿原子、MT 先行、maker 单腿、LEGGED 即回滚 | positions/legs |
| G8 | 看护 | 交易部 + 风控部 | 收割/止损/carry 失联/灾难带/CLOSING 超时升级 | 平仓 |
| G9 | 结算 | 账本部 | 单源净额、completeness、NAV 日切 | settlements、NAV |
| G10 | 复盘 | 复盘部（复盘员） | 判决书、预估 vs 实际回写 G2 | `position_reviews`、stats |
| G11 | 淘汰/升级 | 投资部 | 硬判据自动；投委会月复核可反裁 | `fin_strategy` 态变 |
| IR | 汇报 | 投资者关系部 | 周报/日报/事故/请求三要素 | 飞书 + 投资人页 |

时间尺度：G0–G3 常驻自动（秒级流 + 小时级扫描）；G4 首次真金等人翻开关（小时–天）；G5–G9 全自动（毫秒–秒）；G10 事件驱动（平仓即判）；G11 自动 + 月复核。**流程里不出现任何「某时去查」**（D-033）。

## 10. 实施路线（D-212 裁定：先搬迁后新件——搬迁票 M0–M3 见 `docs/搬迁清单.md` §9；以下为 M4+ 新件顺序）
